## `ИНСТРУКЦИЯ.md`

```markdown
# Расчёты с подрядчиками — инструкция

Приложение отвечает на два вопроса бухгалтера: **за что мы уже рассчитались** и **сколько осталось заплатить** — по каждой работе и по каждому договору, на выбранную дату.

Все суммы считаются в копейках, без округления до рублей. Данные берутся только из папки `data/`.

---

## Шпаргалка

| Хочу | Делаю |
|---|---|
| Открыть отчёт | `python run.py` — браузер откроется сам |
| Узнать, какими платежами закрыта работа | раздел **Работы** → нажать строку |
| Посмотреть отчёт на другую дату | поле **Дата** в шапке |
| Проверить, что будет при другом правиле разнесения | тумблер **Сравнить** в фильтрах раздела «Работы» |
| Добавить платёж | кнопка **Добавить** в шапке (или клавиша `n`) |
| Отменить только что добавленное | кнопка **Отменить** в уведомлении справа внизу |
| Выгрузить в Excel | **Скачать** → нужный CSV |
| Распечатать | кнопка с принтером в шапке |
| Остановить | `Ctrl + C` в окне запуска |

## 1. Запуск

Нужен **Python 3.10 или новее**. Устанавливать библиотеки не надо — приложение использует только стандартную библиотеку.

**Windows:** двойной клик по `Запустить.bat` или в терминале:
```
cd C:\Users\Яков\Desktop\candidate-B
python run.py
```

**macOS / Linux:**
```
cd путь/до/candidate-B
python3 run.py
```

В окне появится:
```
  Расчёты с подрядчиками — интерфейс запущен
  ────────────────────────────────────────────────────
  Откройте в браузере:  http://127.0.0.1:8765/
  Файлы данных:         ...\candidate-B\data
  Процесс:              PID 12345, Python 3.12.x
  Дата по умолчанию:    2026-11-10
  Новые записи:         кнопка «Добавить», отмена — в уведомлении
  Журнал правок:        ...\data\_journal.jsonl
  Остановить:           Ctrl + C
```

Браузер открывается сам. Если не открылся — скопируйте адрес из строки «Откройте в браузере». **Адрес всегда берите из окна запуска:** если порт 8765 занят прежним запуском, приложение займёт следующий свободный и напечатает его.

Остановить — `Ctrl + C` в окне запуска или закрыть окно. Данные и отчёты остаются на месте.

**Дополнительные ключи:**

Работает только на вашем компьютере (`127.0.0.1`), в сеть ничего не отдаётся.

## 2. Экран за 30 секунд

**Шапка (всегда на виду):** дата отчёта, правило разнесения, «Добавить», «Пересчитать», «Скачать», печать, смена темы. Навигация: Обзор · Работы · Платежи · Пояснения.

**Обзор** — пять плиток с итогами, блок «Требует подтверждения» и карточка на каждый договор с полосой: каждый цветной отрезок — деньги, лёгшие на конкретную работу.

## 3. Главное действие: узнать, за что мы рассчитались

Пример на реальных данных, отчёт на **10.11.2026**:

1. Раздел **Работы**.
2. Найдите `W-14 Съёмка: осень` (можно нажать `/` и набрать «осень»).
3. В колонке «Выплачено» стоит **100 000,00**, под суммой подписано: `прямой 15 000,00 · из аванса 85 000,00`.
4. Нажмите строку. Справа откроется разбор:
   - цена 100 000,00 · выплачено 100 000,00 · осталось 0,00;
   - **Из чего сложилась сумма:** `P-3 Материалы для съёмки` — 15 000,00 (оплачен 25.10.26, платёж прямо на эту работу) и `P-1 Аванс 50%` — 85 000,00 (оплачен 01.09.26, доля аванса по договору);
   - зелёная строка **«Сумма частей равна выплаченному — 100 000,00 ₽»**;
   - **Что было с работой:** запланирована → принята 28.10.26 → на дату отчёта «принята».

Так видно не только сумму, но и **какие именно деньги** её закрыли. То же самое в обратную сторону: раздел **Платежи** → нажать `P-1` → «На что легли эти деньги»: 100 000 на `W-11`, 100 000 на `W-12`, 85 000 на `W-14`, 15 000 на `W-15`, и строка «Разложено полностью, до копейки».

Полоска под суммой в таблице: **синяя часть** — привязанные платежи, **оранжевая** — доля аванса.

## 4. Как читать цифры

| Колонка | Что значит |
|---|---|
| **Цена** | стоимость работы по договору |
| **Выплачено** | деньги, реально ушедшие подрядчику **на выбранную дату** |
| **Осталось** | цена минус выплачено; по отменённой работе — прочерк |
| **прямой** | платёж, привязанный именно к этой работе |
| **из аванса** | доля платежа по договору без привязки к работе |
| **Статус на дату** | состояние работы на дату отчёта, а не на сегодня |
| **В очереди** | платёж заведён, но деньги не ушли — долг не уменьшает |
| **Возвращено** | деньги вернулись подрядчиком — вычтены из выплаченного |
| **Не разнесено** | деньги на договоре, которым не нашлось работы |

**Почему по договору две цифры остатка.** «Осталось / договор» считается от суммы, подписанной в договоре. «Осталось / работы» — от цен неотменённых работ. По D-1 это **285 000,00** и **185 000,00**: разница 100 000,00 — отменённая работа `W-13`, которая осталась в сумме договора. Приложение не прячет расхождение, а выносит его в блок «Требует подтверждения»: нужно допсоглашение или подтверждение, что платить по ней не надо.

**Почему статус может отличаться от выгрузки.** В файлах статус стоит «на момент выгрузки». `W-23 Упаковка` принята 11.11.2026, поэтому на 10.11.2026 она ещё **план**, и под статусом подписано «в выгрузке: принята».

**Что не попало в отчёт на 10.11.2026 и почему** (видно в разделе «Платежи», колонка «На дату отчёта»):
- `P-2` 50 000,00 — подрядчик вернул 10.09, из оплаты вычтено;
- `P-4` 150 000,00 — в очереди, деньги не ушли;
- `P-8` 20 000,00 — оплата 12.11, позже даты отчёта.

## 5. Дата и правило разнесения

**Дата.** Поле «Дата» в шапке. Поставили другую — отчёт пересчитывается сразу. В отчёт входит всё, что оплачено **в указанную дату включительно**.

Полезная проверка: поставьте **17.11.2026**. По D-2 учтётся `P-8`, выплачено станет 95 000,00 при договоре 90 000,00, и приложение покажет **переплату 5 000,00** и «не разнесено 5 000,00». Это повод проверить, не задвоились ли `P-7` «Доплата» и `P-8` «Остаток».

**Правило.** Платежи без привязки к работе надо как-то разложить по работам. В шапке — переключатель:

- **сначала принятые** (по умолчанию): аванс закрывает работы в порядке сдачи — сначала полностью принятые по дате приёмки, потом плановые по номеру. Отменённые не участвуют.
- **пропорционально**: аванс делится между работами пропорционально непокрытому остатку цены, до копейки.

**Тумблер «Сравнить»** (фильтры раздела «Работы») добавляет колонку «При другом правиле» с разницей. На 10.11.2026 по D-1:

| Работа | сначала принятые | пропорционально |
|---|---|---|
| W-11 | 100 000,00 | 61 855,67 |
| W-12 | 100 000,00 | 61 855,67 |
| W-14 | 100 000,00 | 67 577,32 |
| W-15 | 15 000,00 | 61 855,67 |
| W-16 | 0,00 | 61 855,67 |

**Итоги по договору при этом не меняются:** выплачено 315 000,00, остаток по договору 285 000,00. Меняется только то, за какие работы мы считаем рассчитавшимися. Это решение нужно подтвердить бухгалтеру — оно записано в `DECISIONS.md`, пункт 7.

## 6. Лента времени

Раздел **Платежи**, слева. По горизонтали — месяцы, по вертикали — дорожка на каждый договор.

- **Размер точки** — сумма платежа.
- **Зелёная заливка** — учтён в оплате.
- **Перечёркнутая** — возвращён.
- **Контур без заливки** — деньги не ушли (очередь).
- **Жёлтая пунктирная линия** — дата отчёта. Всё правее неё в расчёт не входит: на 10.11 точка `P-8` стоит справа от линии — это и есть причина, по которой она не учтена.

Наведение показывает сумму и причину, нажатие открывает разбор платежа.

## 7. Замечания к данным

Узкая колонка справа от ленты. Три группы:

- **Ошибки** — строку не удалось прочитать, она исключена из расчёта (суммы могут быть неполными).
- **Подтвердить** — то, что требует решения бухгалтера: отменённая работа в сумме договора, нераспределённые деньги, переплата.
- **Пояснения** — почему цифра именно такая: платёж позже даты, возврат, статус на дату отличается от выгрузки.

Группы сворачиваются. Под каждым замечанием — короткое объяснение, чем это важно. Тот же список выгружается в CSV.

Если замечаний нет, колонка показывает «Все строки прочитаны, суммы сходятся».

## 8. Как добавить запись

Кнопки: **Добавить** в шапке (открывает форму платежа), **＋ Работа** в разделе «Работы», **＋ Договор** в обзоре. Клавиша `n` (или `т` в русской раскладке) — новый платёж.

Форма открывается справа, вкладки **Договор / Работа / Платёж** переключаются сверху.

### Платёж

| Поле | Что подставляется / что вписать |
|---|---|
| Номер платежа | предлагается следующий свободный (`P-9`), можно изменить |
| Договор | список договоров; при смене договора привязка к работе сбрасывается |
| Работа | «— без привязки к работе —» или конкретная работа этого договора |
| Назначение | как в платёжке, например «Остаток по договору» |
| Сумма | понимает `150000`, `150000.00`, `150 000,00` |
| Статус | оплачен / в очереди на оплату / возвращён подрядчиком |
| Когда заведён | подставляется дата отчёта |
| Когда деньги ушли | появляется для «оплачен» и «возвращён» |
| Когда вернули | появляется только для «возвращён» |

Под суммой — подсказка: **«Осталось по договору … ₽, по работам … ₽»**, а если выбрана работа — **«Осталось по работе … ₽ из … ₽»**. Удобно не переплатить.

Если оставить работу пустой, платёж разнесётся по выбранному правилу — как `P-1`.

### Работа

Номер, договор, название, цена, статус. Для «выполнена и принята» появится обязательное «Когда принята», для «отменена» — «Когда отменена». Для «запланирована» даты не нужны.

### Договор

Номер, подрядчик, сумма, дата подписания.

### Что происходит после нажатия «Добавить запись»

1. Запись проверяется (обязательные поля, формат суммы, существование договора и работы, возврат не раньше оплаты).
2. Дописывается в соответствующий CSV в `data/`.
3. Отчёт пересчитывается, новая запись сразу видна в таблицах и на ленте.
4. Справа внизу появляется уведомление с кнопкой **Отменить**.

Новые записи помечены **фиолетовой точкой** в таблицах и меткой «добавлено вручную» в разборе. Счётчик таких записей виден в шапке обзора.

**Если сервер отказал** — причина показывается прямо в форме красным блоком: «Договор D-3 уже есть в выгрузке», «Работа W-24 относится к договору D-2, а не к D-1», «Дата возврата раньше даты оплаты», «contracts.csv занят другой программой». Исправьте поле и нажмите снова — введённое не теряется.

## 9. Изменить, удалить, отменить

**Изменить и удалить можно только записи, добавленные через приложение.** Строки исходной выгрузки защищены: в их разборе написано «Запись из исходной выгрузки — правки вносятся в учёте». Это сделано, чтобы сверка с учётом оставалась возможной.

- **Изменить** — та же форма с заполненными полями; номер записи менять нельзя.
- **Удалить** — сначала кнопка, потом подтверждение «Да, удалить / Отмена».
- Защита от потери связей: договор с работами или платежами удалить нельзя, работу с привязанными платежами — тоже. Приложение напишет, что удалить сначала.

**Отмена.** После добавления, изменения или удаления в уведомлении есть кнопка (**Отменить** / **Вернуть**), она живёт около 9 секунд. Нажатие возвращает всё как было. Если уведомление исчезло — удалите лишнюю запись вручную или восстановите файл из резервной копии (раздел 13).

## 10. Выгрузка в Excel и печать

**Скачать** в шапке:

| Пункт | Файл | Что внутри |
|---|---|---|
| По работам | `works_2026-11-10_fifo.csv` | цена, выплачено, осталось, привязанные и из аванса, очередь, возврат |
| Итоги по договорам | `contracts_…csv` | сумма, выплачено, оба остатка, очередь, возврат, переплата, разница |

| Замечания к данным | `issues_…csv` | ошибки, предупреждения, пояснения |
| Полный отчёт | `report_…json` | для разработки |

CSV сделаны под русский Excel: разделитель `;`, кодировка UTF-8 с BOM, десятичная запятая. Открываются двойным кликом, «Мастер импорта» не нужен. Выгружается то, что сейчас на экране — с выбранной датой и правилом.

**Печать** (кнопка с принтером) — печатает или сохраняет в PDF все разделы без шапки, кнопок и фильтров, на белом фоне. Для светлого экрана есть тема «Бумага» — кнопка со солнцем/луной.

## 11. Вид под себя

- **Поиск** в работах: клавиша `/`, ищет по номеру, названию, договору и подрядчику.
- **Фильтры**: по договору, по статусу (Принятые / План / Отменённые), тумблер «С долгом».
- **Сортировка**: клик по заголовку колонки; повторный клик меняет направление.
- **Сбросить** — снимает фильтры раздела «Работы».
- Дата, правило, тема, фильтры и отметки в чек-листе **запоминаются в браузере**. Чтобы вернуться к контрольной проверке, просто поставьте дату 10.11.2026 и правило «сначала принятые».
- **Клавиши:** `/` — поиск, `n` — новый платёж, `Esc` — закрыть панель, `Enter` на строке — открыть разбор.

В разделе **Пояснения** есть чек-лист «Что нужно подтвердить» с шестью галочками (правило разнесения, отменённая работа в сумме договора, очередь, возвраты, граница даты, ручные записи). Отметки сохраняются — можно отмечать по мере проверки.

## 12. Если что-то не так

| Что вижу | Причина и что делать |
|---|---|
| Фиолетовая плашка «Запись выключена: этот адрес обслуживает старый сервер», в подвале «запись выключена» | На этом порту висит прежний запуск. Откройте адрес из строки «Откройте в браузере» в окне запуска. Или закройте старый процесс: `python run.py --kill-stale`. Отчёт при этом показывается верно, недоступна только запись. |
| Кнопки «Добавить» серые | То же самое — режим «только чтение». |
| `No module named payreport` | Запускаете не из корня проекта. Сначала `cd` в папку, где лежат `run.py`, `payreport`, `data`. |
| `Не найден пакет payreport` / нет файла интерфейса | Не сохранены `payreport/store.py`, `payreport/webapp.py` или `payreport/ui/index.html`. |
| `SyntaxError` при запуске | Python старше 3.10. Проверьте `python --version`. |
| Запустился Python из Inkscape | VS Code выбрал не тот интерпретатор. Выберите Python 3.12 (`Ctrl+Shift+P` → Python: Select Interpreter) или запускайте `python run.py` из терминала. |
| «Отчёт не построился» с текстом ошибки | Приложение не смогло прочитать данные или суммы не сошлись. Текст ошибки покажет причину; кнопка «Повторить» повторяет попытку. |
| `занят другой программой` при сохранении | CSV открыт в Excel. Закройте файл и повторите. |
| Кракозябры в консоли Windows | `chcp 65001` перед запуском; в браузере и CSV кодировка корректная. |
| Не нашёл свободный порт | `python run.py --port 9100`. |
| Хочу проверить, что расчёт не сломался | `python -m unittest discover -s tests -v` — должно быть `Ran 16 tests … OK`. |

## 13. Что происходит с файлами

**Меняется:**
- `data/contracts.csv`, `works.csv`, `payments.csv` — только если вы сами добавляете, изменяете или удаляете записи через интерфейс.
- `data/_journal.jsonl` — журнал всех действий (что, когда, что было до). Создаётся при первой записи. По нему работает отмена.
- `data/*.csv.bak` — копия файла **перед последней перезаписью** (изменение или удаление). Добавление дописывает строку и копию не делает.
- `out/` — файлы отчёта, если пользуетесь командным режимом.

**Не меняется:** исходные строки выгрузки. Приложение не редактирует и не удаляет их, не «подгоняет» цены под сумму договора и не пересчитывает данные в файлах.

**Важно про копии:** `.bak` хранит только одно предыдущее состояние, а не исходную выгрузку. Чтобы откатить все ручные правки, удалите добавленные записи через интерфейс (они помечены) или верните исходные CSV из архива задания.

**Не редактируйте CSV в Excel, пока сервер запущен:** Excel может заблокировать файл или поменять разделители и кодировку. Для ввода есть формы в приложении.

## 14. Командный режим (для проверки и автоматизации)

Тот же расчёт без браузера:

```
python -m payreport --date 2026-11-10
python -m payreport --date 10.11.2026 --allocation proportional --out out-prop
python -m payreport --date 2026-11-17 --format console
python -m payreport --help
```

| Ключ | Значение |
|---|---|
| `--date` | обязательна; `2026-11-10` или `10.11.2026` |
| `--data` | папка с CSV, по умолчанию `data` |
| `--out` | куда писать файлы, по умолчанию `out` |
| `--allocation` | `fifo` (по умолчанию) или `proportional` |
| `--format` | `console,csv,json` по умолчанию |

Коды возврата: `0` — всё хорошо, `1` — отчёт построен, но часть строк исключена с ошибкой (смотрите `out/issues.csv`), `2` — построить не удалось.

## 16. Чего приложение не делает

- Не поддерживает **частичный возврат**: в выгрузке нет суммы возврата, только дата, поэтому возврат считается полным.
- Только рубли, без разбивки НДС и без валютных операций.
- Один платёж — один договор;把工作 разнести по двум договорам нельзя.
- Даты суточные: время в выгрузке отсутствует и не учитывается.
- Не проверяет юридическую допустимость расхождения «сумма договора ↔ цены работ» — только сообщает о нём.
- Не заменяет учёт: это отчёт для сверки, а не платёжная система. Деньги никуда не отправляются.

Все спорные места и принятые допущения описаны в `DECISIONS.md`. Что нужно подтвердить бухгалтеру — в разделе **Пояснения** приложения и в конце `DECISIONS.md`.
```
